# Treasure Archive and Assault Closure 1.0.38

## Treasure archive decision

Treasure runtime research is closed for the current Lua implementation. The exact static catalog, 11 generated classes, source module, historical runtime reports, and confirmed presence-to-absence observation remain preserved.

The module is disabled and excluded from `probe_order`. The active runtime therefore performs no Treasure `FindAllOf` calls. This is an operational archive, not deletion and not promotion of diagnostic inference into production truth.

## Assault-only runtime

`assault_condition_transition` is the only automatic runtime probe. It issues one known read-only `CUnexpectedMissionInStandAlone` query per scheduler tick with `ISAll=false`, fresh handle resolution, per-call validity checks, and fail-closed session disablement.

One complete 40-target rotation takes approximately 40 seconds. Staggering preserves transition coverage while avoiding the previous ten-call burst.

## Remaining closure gate

The current boolean is confirmed as an in-zone or active-context observation. It is not yet a persistent completion bit. Closure still requires one controlled sequence containing baseline, task entry, task completion, remaining nearby or explicit task exit context, and post-exit diagnostics. A true-to-false transition alone must not be labeled as completion.

Boss research remains frozen. Dash functionality is outside DataProbe scope and must be implemented later in the production mod after Assault evidence is accepted.
