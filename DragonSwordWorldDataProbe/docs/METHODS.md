# 目前所有数据采集方法总结

| 方法 | 能得到什么 | 全图完整性 | 性能/风险 | 结论 |
|---|---|---:|---:|---|
| PAK + GeneratedGameData XML | 完整静态清单、坐标、生成条件、刷新规则 | 完整静态世界 | 低运行时成本；解码器需正确 | **静态目录主方案** |
| SQLCipher 存档快照/逻辑表 | 未加载区域也存在的持久状态 | 完整持久状态 | 文件变化时读取成本低 | **动态可用性主方案** |
| 精确 UE4SS 类/属性读取 | 类名、字段路径、全局管理器当前值 | 取决于对象生命周期 | 白名单一次读取较低 | Schema 发现/验证 |
| 白名单 bounded FindAllOf | 当前已加载对象样本 | 不完整，受 World Partition 限制 | 中等，目标过大会卡 | 诊断模块，默认关闭 |
| UI ListView/Entry | UI 已构建的数据和显示状态 | UI 依赖、短暂 | 中等且不完整 | 映射辅助，不作最终状态源 |
| 精确函数 Hook | 实时状态变化 | 只覆盖 Hook 后事件 | 中高；错误签名会崩溃 | 仅明确函数时实验启用 |
| ReceiveDestroyed/ReceiveEndPlay | Actor 生命周期 | 不是击杀 | 高；已复现 UE4SS 原生崩溃 | **禁止用于通用发现** |
| DPS 全伤害统计 | 每次伤害、目标对象、击杀线索 | 仅本地战斗 | 高频聚合/UI 很重 | 当前目标不需要 |
| 本地 kill cache | Mod 启动后的事件状态 | 启动前状态缺失 | 低 | Boss 已有更完整存档方案，拒绝重复实现 |
| 任务 Controller/UI 完成状态 | 某些任务入口和页面标记 | 未找到完整全局列表 | 多次扫描收益低 | 不属于最终突击方案 |
| 原生数据库连接/密钥 Hook | 已解密连接、SQLCipher 参数 | 理论完整 | 原生 ABI/注入风险 | 保留实验源码，默认不运行 |
| 常见密码猜测 | 可能打开加密 DB | 无确定覆盖 | 低收益 | 已排除常见候选，不再作为主线 |
| 通用 UnrealPak/repak 搜索 | PAK 内容 | 依赖外部工具/格式 | 低 | 已被现成 PakReaderCore + ooz 链替代 |
| UE4SS ObjectDump 静态筛选 | 类、函数、属性名 | Schema 级 | 低 | 辅助方法 |
| PAK 相邻 offset/mask 穷举 | 偶尔产出“看似有效”XML | 不可靠 | 会产生邻项假阳性 | **禁止** |

## 总体原则

完整功能应拆成四层：

1. **静态目录层**：PAK XML 给出“有什么、在哪里、什么条件生成、如何刷新”。
2. **持久状态层**：存档表给出“当前是否死亡/冷却/开关状态”。
3. **运行时验证层**：只验证明确的类、字段、当前天气或开关；不承担全地图真相。
4. **分析层**：保留源文件、行、字段和值，生成带置信度的候选关联。

Boss 已验证的正确结构是静态目录 + `tb_actor_respawn`。突击应复用同一结构，而不是另建任务 UI、DPS 或 60 秒强制刷新逻辑。
